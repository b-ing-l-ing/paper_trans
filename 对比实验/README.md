# 对比实验：代码读图 vs LLM 读图

## 目的

对比「咱们项目写的代码读柱状图」和「纯 LLM 直接读图」的准度。

- **代码读图方**：`paper2data` 的 `figure_to_text`（代码切框 + 标定 + 反算）
- **LLM 读图方**：纯 vision 估读（公平 prompt：只给「从左到右、从上到下读出所有柱子」，不给刻度/标签/系列结构提示）

## 两套评测集（`--set`）

| set | 图 | 真值来源 | 用途 |
|---|---|---|---|
| `dev`（默认）| `images/` 4 张 | `benchmark.json`：论文1 表4/表5（**表格真值**）+ 论文2 人工估读 | 调参用，别写进论文 |
| `blindset` | `blindset/erased/` 2 张 | `benchmark_blindset.json`（由 `blindset/benchmark.csv` 转来，87 个真值）| 🚨 **2026-10-16 起已降级为开发集**（见下）|

> 🚨 **`blindset` 这批（`24_fig3`/`yansuan_fig4`）2026-10-16 已降级为开发集。**
> 原因：继续诊断「路由/判据」必须能拿真实样本定判据，定了它就不再 held-out。**它的结果不能再当无偏估计写进论文。**
> **用户之后会另找新图重建留出集**——**那批**才按「跑完即冻结、不许回头调」保护。`--set` 机制保留，将来新图沿用。

⚠️ **盲测集用 `erased/`（PS 擦掉柱顶印值的那版）**——那才逼两边都走「标定 + 反算」。带印值的 `original/` 在 benchmark 的 `image_with_labels` 字段里，供「读印值可不可靠」那个条件另用。

⚠️ **开发集是调参集**：我们的代码是在这 4 张图上调的，**别拿它的成绩下结论**（数据泄漏）。

## 运行（三步；脚本用 `__file__` 定位目录，在哪个目录跑都行）

```bash
# 开发集
python 对比实验/code_read.py
python 对比实验/llm_read.py
python 对比实验/score.py

# 盲测集（输出自动带 _blindset 后缀，不覆盖开发集结果）
python 对比实验/code_read.py --set blindset
python 对比实验/llm_read.py --set blindset
python 对比实验/score.py    --set blindset
```

**每步的产出**（`<set>` = 空 或 `_blindset`）：

| 文件 | 内容 |
|---|---|
| `code_result<set>.json` | 代码读图的**原文**（喂给 score）|
| `code_result<set>.csv` | 人可读：图 / 面板 / 标签 / 值 / 来源(反算 or 约-落回) |
| `llm_result<set>.json` | LLM 读出的数值列表 |
| `llm_result<set>.csv` | 人可读：图 / 序号 / 值 |
| `score_detail<set>.csv` | 逐根柱子：真值 / 代码读值 / 是否约 / 代码标签 / 归属对? / 误差 / LLM 读值 / 误差 |
| `score_summary<set>.csv` | 每张图的汇总指标 |

## 评分口径（重要，别用老口径）

**主指标只测数值、不测归属**：两侧按**全局最优值配对**（DP，最小化总相对误差），**不看标签、不看输出顺序**——因为 LLM 侧压根没有标签，按标签配会让代码单方面占便宜。

| 列 | 含义 |
|---|---|
| 代码读出数 / 反算数 / 落回数 | 总读出、其中**代码反算**得到的、其中是 **vision 落回**的 |
| 代码未解析行 | 有 `- ` 头、带冒号却匹配不上的行（旧版**静默丢弃**，不留痕）|
| 覆盖率% | 配对数 ÷ **真值总数**（漏读算没配上）|
| 多检 | 读出来但没配上真值的（多余柱子）|
| **代码标签正确率%** | 配上的对里，逐条标签对的比例 |
| **代码归属正确率%** | 标签对 **且** 面板对——**只在面板检查真生效时**才算，否则留空 |
| 面板生效对数 | **>0 才代表上一列有含义** |
| 代码平均相对误差% / 准确率±5% | **落回值不计入**；准确率分母 = **真值总数**，漏检算不命中 |

**五个坑**（读表前先看）：
1. **「落回」不是看「约」字**。判据是「这个块里有没有 `系列N（…）:` 头」——代码反算必带，vision 落回从不带。**vision 经常不写「约」**，只看「约」字会把整轮落回记成代码反算（实测 `24_fig3` 五轮落回值一个「约」都没有）。
2. **「归属%」多半是空的，那是如实反映**。代码切框把面板命名成「子图N」，抠不出「图N」标记 → 面板**压根没被检查过**，所以置空。旧版在没生效时恒判「对」，把它退化成标签匹配率、却摆出查过面板的样子。**空 ≠ 满分**，要一起看「面板生效对数」。
3. **主指标不看归属**——代码把「图1 的值」标成「图2(a)」时，按值配对照样能配上。
4. **配对错会记成 ×**——归属率是在配对结果上算的；两个真值挨太近时 DP 会交叉配对，标签跟着对不上（那是配对的锅，不是代码标错）。
5. **多检不进准确率**——读出 36 对上真值 30 仍可拿高分，只有「多检」那一列提醒。

## 抖动：必须跑多次

vision 服务端**有抖动**（同图两次跑，子图 bbox 和上报颜色都可能不同）。所以：

- 单次跑的数字**不能直接写论文**；
- 用 `variance.py` 跑 N 轮（每轮**关掉 vision 缓存重新抽**），报「均值 ± 跨度」：

```bash
python 对比实验/variance.py                  # 开发集，默认 5 轮
N_RUNS=10 python 对比实验/variance.py --set blindset
# 产出 variance_detail<set>.csv；单轮失败不打断整轮（记 run{i}_error.txt 跳过）
```

## 可复现：vision 缓存

`vision_cache.py` 把 vision 调用按「图 bytes + prompt + 模型名」哈希缓存 → **同图复跑逐字节一致**。

- 默认开；`COMPARE_VISION_CACHE=off` 关闭（`variance.py` 就是这么重抽的）；
- 删 `对比实验/.vision_cache/` 刷新；
- 只包 vision 那一层，**改 `chart_extract`/`figure_extract` 的算法逻辑，结果照样变**；
- **生产代码一行没动**（靠 monkeypatch）。
